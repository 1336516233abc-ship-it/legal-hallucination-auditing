# 合同答案人工盲评说明

此包含两个模型、三个 Agent 变体对同样 10 个问题生成的 60 条输出。已经随机打乱并隐藏模型和变体身份；当前没有任何人工评分。请两位评审者各保留一份，独立填写。

## 开始

1. 双击 review.html，填写评审者代号；无需登录或 API。
2. 先各做前 6 条作校准。只根据原合同和问题判断，讨论判定规则后再独立继续。若校准后改变口径，重新复核受影响条目。
3. 判断输出类型，再填写实质答案的全部原子断言。包括标签表达的任务结论；absent 和 neutral 不自动等于弃权。
4. 选中合同原文，点击相应断言的“加入左侧所选证据”。supported / contradicted 需精确原文；not_enough_information 需说明不足依据。不得为了完成表格制造证据或标签。
5. 勾选完成并导出 JSON。离开前必须导出，页面不会自动保存或上传；下次导入此文件继续。不要把仍含空评分的文件当已完成人工评审。

## 统计口径

本包主要评审用户可见的最终答案及任务标签。3 条格式失败、另外 11 条因 grounding error 被隐藏的输出单独计数，不当作 supported 或零幻觉。对于没有错误的 CUAD absent，空抽取文本不算展示失败，仍需评审 absent 的结论。

实质答案中，每条事实断言判为 supported、contradicted 或 not_enough_information。断言级未支持率 = 后两类断言数 / 已完整评审的断言数；答案级未支持率 = 至少有一条后两类断言的实质答案数 / 已完整评审的实质答案数。必须同时报告覆盖率、格式失败数、隐藏数、弃权数及各分母。已标记需要裁决的记录先不进入完成指标。

本包选用“用户可见答案”作为评审对象；原提案的解释断言口径还可能包含被拦截的候选输出。团队须在正式比较前确认二者区别。原始候选响应保留用于排查，不把被拦截文本当成已经向用户交付的答案。若还要量化模型候选本身的幻觉，应另建候选输出评审，不能混用分母。

这 60 条只是已有试点，只有 10 个不同问题，不含正式 Direct/RAG 配对输出，也不估计全量幻觉率、答案完整性、弃权精确度或修订成功率。

## 协调与裁决

协调者收齐两名真人各自的 JSON 后，比较同一 blind_id 的输出类型、断言边界和判定。记录分歧、讨论理由和裁决结果。当前工具仅校验单份评分和统计该份评分中的完整记录，不自动生成一致性、裁决或“双人真值”。提交前不要把协调者专用的 private_key.json、gold_reference.json 或已有案例分析发给盲评者。

评分校验命令见交付目录 README。初始空白表运行后所有支持性指标仍为 null，这表示未评估。
