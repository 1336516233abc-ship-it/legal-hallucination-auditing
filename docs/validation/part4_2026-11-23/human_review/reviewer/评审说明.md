# Contract Answer Manual Blind Review Instructions

This package contains 60 outputs generated by two models and three Agent variants for the same 10 questions. The model and variant identities have been randomized and hidden; there is currently no human scoring. Please have two reviewers each keep a copy and complete them independently.

## Getting Started

1. Double-click review.html and enter your reviewer ID; no login or API required.
2. First, each reviewer should complete the first 6 items for calibration. Judge based solely on the original contract and questions, discuss the judgment rules, then continue independently. If calibration changes your approach, re-review affected items.
3. Determine the output type, then fill in all atomic claims in the substantive answer. Include task conclusions expressed by labels; absent and neutral do not automatically equal abstention.
4. Select the contract text and click “Add selected evidence to the left” for the corresponding claim. supported / contradicted require exact text; not_enough_information requires explanation of insufficient evidence. Do not fabricate evidence or labels to complete the form.
5. Check complete and export JSON. You must export before leaving; the page does not auto-save or upload. Import this file next time to continue. Do not treat files still containing blank scores as completed human reviews.

## Statistical Criteria

This package primarily reviews the final answer visible to users and task labels. 3 format failures and another 11 outputs hidden due to grounding errors are counted separately, not treated as supported or zero hallucination. For error-free CUAD absent, empty extracted text does not count as display failure; the absent conclusion still needs review.

In substantive answers, each factual claim is judged as supported, contradicted, or not_enough_information. Claim-level unsupported rate = latter two claim types / fully reviewed claims; answer-level unsupported rate = substantive answers with at least one latter two claim types / fully reviewed substantive answers. Must simultaneously report coverage, format failure count, hidden count, abstention count, and all denominators. Records marked for adjudication should not enter completion metrics first.

This package uses “user-visible answers” as the review object; the original proposal's claim interpretation criteria may also include intercepted candidate outputs. The team must confirm the difference between the two before formal comparison. Original candidate responses are retained for troubleshooting; do not treat intercepted text as answers already delivered to users. If you also want to quantify the hallucinations in the model candidates themselves, a separate candidate output review should be created; denominators cannot be mixed.

These 60 items are only an existing pilot with only 10 different questions, do not contain formal Direct/RAG paired outputs, and do not estimate overall hallucination rates, answer completeness, abstention precision, or revision success rates.

## Coordination and Adjudication

After the coordinator collects JSON from both human reviewers, compare the output type, claim boundaries, and judgments for the same blind_id. Record disagreements, discuss rationales, and adjudication results. The current tool only validates single scores and statistics for complete records in that score; it does not automatically generate consistency, adjudication, or “dual-human ground truth”. Before submission, do not send coordinator-only private_key.json, gold_reference.json, or existing case analyses to blind reviewers.

For scoring validation commands, see the delivery directory README. After running the initial blank form, all support metrics remain null, indicating unevaluated.
